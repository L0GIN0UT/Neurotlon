# ID участника и QR

## ID

- Формат: `NT` + две цифры, `NT01`…`NT99`. На мероприятие создаётся 20 (`NT01`…`NT20`), количество — в настройках.
- Регулярное выражение: `^NT(0[1-9]|[1-9][0-9])$`. Оно же в `openapi.yaml` (`ParticipantCode`).
- ID не секрет: он напечатан на бейдже. От подмены защищает окно «Это я», а не ID.

## QR

- Содержимое — ровно ID, без префиксов и ссылок: `NT07`. Читается любым сканером, совпадает с тем, что вводят руками.
- Уровень коррекции ошибок `M`, сторона на бейдже не меньше 3 см, рядом крупно напечатан тот же ID.
- QR, содержимое которого не проходит нормализацию ниже, игнорируется (чужие коды в кадре вебки).

## Ручной ввод и нормализация

Лаунчер, планшет и сервер приводят ввод к ID одинаково:

1. Убрать пробелы, `-` и `_`, перевести в верхний регистр.
2. Кириллические `Н` и `Т` в префиксе считать латинскими `N` и `T`.
3. Принять: `NT` + 1–2 цифры или только 1–2 цифры. Дописать ведущий ноль до двух цифр.
4. Результат проверить регулярным выражением выше, иначе — ошибка ввода.

Так волонтёр может ввести просто `7`. Проверочные примеры для всех реализаций — [`participant-code.cases.json`](participant-code.cases.json).
