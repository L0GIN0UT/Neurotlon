# Протокол «BCI-мост → игра»

Версия 1. Схема сообщений — [`bridge-protocol.schema.json`](bridge-protocol.schema.json).

## Транспорт

- TCP `127.0.0.1:8765` (порт в настройках стенда). Мост — сервер, игра — клиент. Пока подключена одна игра, новое подключение сразу закрывается.
- Каждое сообщение — JSON-объект в одну строку UTF-8, заканчивается `\n` (NDJSON). Поле `type` задаёт вид сообщения.
- Неизвестное `type` или поле получатель игнорирует. Несовместимое изменение — новый `protocol`.

## Сигналы

| Имя | Датчик | Значение | Где |
|---|---|---|---|
| `eeg` | BrainBit | расслабление 0…1 | дартс, футбол |
| `emg` | Callibri | сила сокращения 0…1 | дартс, футбол |
| `emg_left`, `emg_right` | два Callibri | сила сокращения 0…1 | понг |

Значение уже отфильтровано, откалибровано и обрезано до 0…1. Игра не знает, откуда оно: датчик или эмулятор.

## Сообщения

**Мост → игра**

- `hello` — сразу после подключения: версия протокола, список сигналов с состоянием датчиков и необязательные поля:
  - `features` — что умеет мост: `burst` (событие резкого сокращения), `emg_cycle` (шаг `cycle` и `segments`), `baseline_duration` (`duration_s` у `baseline`). Нет поля или функции в списке — мост старый, игра обходится без неё;
  - `eeg_method` — метод обработки ЭЭГ, `emotions` или `alpha`; только если среди сигналов есть `eeg` (см. «Метод ЭЭГ»).
- `sample` — последние значения всех сигналов, около 50 раз в секунду. `valid: false` с `reason` — значение использовать нельзя (артефакт, нет контакта, датчик отключён, данные старше 500 мс).
- `sensor` — смена состояния датчика: `connecting`, `connected`, `disconnected`, `emulated`; заряд в процентах, если известен.
- `calibration` — ход калибровки: `running` с `progress` 0…1, затем `done` или `failed` с `reason`. У шага `cycle` при `running` есть ещё `segment` (номер сегмента с 1), `phase` (`tense` или `relax`) и `phase_left_s` (сколько секунд осталось до конца сегмента): по ним игра показывает «сжать» и «расслабить» и обратный отсчёт. Эмулятор с ускорением `speed` больше 1 отсчитывает `phase_left_s` в секундах калибровки, а не в реальных.
- `burst` — резкое сокращение мышцы (см. «Резкое сокращение»): `signal` (`emg`, `emg_left` или `emg_right`), `t_ms`, `seq` и необязательное `rise` 0…1. `seq` растёт на единицу с каждым событием отдельно для каждого сигнала и начинается заново при новом подключении; по разрыву в `seq` игра видит потерянные события и не считает одно событие дважды.

**Игра → мост**

- `calibrate` — начать шаг калибровки сигнала. Игра показывает инструкции, мост сообщает ход.
  - ЭМГ: `cycle` — чередование напряжения и расслабления (рекомендуется, мост объявляет его в `features` как `emg_cycle`); старые `rest` и `contract` остаются для выпущенных сборок игр.
  - ЭЭГ: `baseline` — спокойно смотреть на точку с открытыми глазами.
  - `cycle`: по умолчанию 5 с напряжения, 5 с расслабления, ещё раз 5 с напряжения и 5 с отдыха (всего 20 с; ритм настраивается в `[emg]` файла `bridge.toml`). Необязательное `segments` задаёт свой ритм: массив `{"phase":"tense"|"relax","s":секунды}`, от 2 до 8 элементов, каждый 2…15 с, сумма не больше 60 с, есть хотя бы один `tense` и один `relax`. Первые 1,5 с каждого сегмента (переход) в расчёт не идут. Покой — медиана уровня по `relax`, максимум — медиана пиков по `tense`; максимум — 90-й перцентиль по напряжениям. Если максимум не выше покоя в `calib_min_ratio` раз (по умолчанию 2), отличается от покоя меньше чем на `calib_noise_k` (по умолчанию 4) разбросов покоя (слабое сжатие, шум вместо сокращения) или точек слишком мало, шаг завершается `failed` с причиной. Неудачный шаг стирает прежний результат калибровки этого сигнала.
  - `rest`: 5 с покоя.
  - `contract`: три сокращения по 3 с с паузой 1 с (всего 12 с, отсчёт с начала шага); игра показывает «сжать / отпустить» по `progress`. Длительности настраиваются в `[emg]` файла `bridge.toml`.
  - `baseline`: 12 с, глаза открыты. Необязательное `duration_s` 5…30 меняет длительность. Шаг и метод ЭЭГ подробнее в «Метод ЭЭГ».
  - `segments` имеет смысл только у `cycle`, `duration_s` только у `baseline`; у других шагов их игнорируют. Значение вне границ, шаг не для этого сигнала (например `cycle` для `eeg`) или сигнал не из профиля мост отклоняет ответом `calibration` со статусом `failed` и причиной; шаг при этом не запускается, а идущая калибровка не прерывается. Пустой `segments` и нулевой `duration_s` считаются отсутствующими (так Unity `JsonUtility` пишет незаданные поля).
- `reset` — сбросить калибровку всех сигналов (новый участник).

Новые возможности добавляются только новыми типами сообщений и необязательными полями верхнего уровня; словарь `sample.signals` не расширяется. Получатель пропускает неизвестное имя сигнала внутри `sample` и не теряет кадр.

## Резкое сокращение

`burst` сообщает, что мышца только что резко сократилась: уровень сигнала быстро вырос от покоя до заметного напряжения. Считает его мост по откалиброванному уровню, игре достаточно слушать событие. Так дартс и футбол запускают бросок и удар.

- Событие — только «пуск». Сила сокращения ни на что не влияет: `rise` (насколько круто вырос уровень) предназначен для показа и журнала, игра не должна брать из него скорость броска или удара.
- Задержка от начала сокращения до события около 0,25 с (окно роста, подтверждение и фильтр уровня). Плавное нарастание и ровное напряжение события не дают.
- После события следующее возможно только после расслабления мышцы и не раньше чем через несколько сотен миллисекунд.
- Событий нет при `valid: false`, до калибровки и сразу после сброса, подключения или переподключения датчика.
- `sample` по-прежнему несёт текущий уровень; игра, которой `burst` не нужен, работает как раньше.

## Метод ЭЭГ

Сигнал `eeg` (расслабление / сосредоточение 0…1) мост считает одним из двух способов, выбор делается в настройках стенда:

- `alpha` (по умолчанию) — по мощности альфа-ритма относительно калибровки;
- `emotions` — встроенные вычисления NeuroSDK Emotions.

Мост сообщает выбранный метод в `hello.eeg_method`. Для игры сигнал одинаков: значение 0…1 и те же шаги калибровки. Калибровка `baseline` проходит с открытыми глазами: участник спокойно смотрит на точку; длительность по умолчанию 12 с.

## Пример

```
← {"type":"hello","protocol":1,"signals":[{"name":"eeg","state":"connected"},{"name":"emg","state":"emulated"}],"features":["burst","emg_cycle","baseline_duration"],"eeg_method":"alpha"}
→ {"type":"calibrate","signal":"emg","step":"rest"}
← {"type":"calibration","signal":"emg","step":"rest","status":"running","progress":0.4}
← {"type":"calibration","signal":"emg","step":"rest","status":"done"}
→ {"type":"calibrate","signal":"emg","step":"cycle"}
← {"type":"calibration","signal":"emg","step":"cycle","status":"running","progress":0.3,"segment":2,"phase":"relax","phase_left_s":3.5}
→ {"type":"calibrate","signal":"emg","step":"cycle","segments":[{"phase":"tense","s":4},{"phase":"relax","s":4}]}
→ {"type":"calibrate","signal":"eeg","step":"baseline","duration_s":15}
← {"type":"sample","t_ms":120450,"signals":{"eeg":{"value":0.41,"valid":true},"emg":{"value":0.73,"valid":true}}}
← {"type":"sample","t_ms":120470,"signals":{"eeg":{"value":0,"valid":false,"reason":"artifact"},"emg":{"value":0.7,"valid":true}}}
← {"type":"burst","signal":"emg","t_ms":120490,"seq":1,"rise":0.8}
```

`t_ms` — монотонное время моста в миллисекундах, только для порядка и задержки, не для часов.

## Эмулятор

Мост с флагом `--emulate` отдаёт те же сообщения без датчиков, значения — с клавиатуры. Состояние датчиков — `emulated`. Делается первым шагом M2.
