# Сервер Нейротлона

API, база данных, расчёт очков, поток табло. Python 3.12, FastAPI, SQLAlchemy + Alembic, SQLite (WAL).

## База данных

Адрес базы — переменная `NEUROTLON_DATABASE_URL` (по умолчанию `sqlite:///./neurotlon.db`).

Применить миграции (из корня репозитория):

```bash
uv run alembic -c server/alembic.ini upgrade head
```

Откатить всё: `uv run alembic -c server/alembic.ini downgrade base`.

Первая миграция создаёт таблицы, триггеры «журнал аудита только на добавление» и три дисциплины
(длительности 120 и 300 с — временные значения, меняются в админке).

## Первый суперпользователь

После миграций (из корня репозитория):

```bash
uv run neurotlon-server create-superuser --login root
```

Пароль (не короче 8 символов) запрашивается интерактивно, в аргументах командной строки его нет.
Остальные аккаунты (админ, судья, волонтёры) и станции создаёт суперпользователь через API
(`POST /api/v1/users`, `POST /api/v1/stations`). Сессия входа живёт 24 часа
(`NEUROTLON_SESSION_TTL_SECONDS`); cookie `Secure`, поэтому вход работает только по HTTPS.
После 5 неудачных входов логин блокируется на 5 минут (так задумано для локальной сети).

## Участники и бейджи

Админ создаёт ID заранее, печатает бейджи и отмечает участников в день мероприятия
(все пути под `/api/v1/participants`, роли `admin` и `superuser`):

1. `POST /generate {"count": 20}` — создаёт недостающие `NT01…NT20`, повтор безопасен.
2. `GET /badges.pdf?codes=NT01,NT02` — PDF для печати (A4, 6 бейджей на лист, линии реза;
   QR только с ID, коррекция `M`, сторона 40 мм). Без `codes` — все участники.
3. `POST /{code}/check-in {"category": "general"|"ovz", "display_name": "..."}` — отметка о приходе;
   `{code}` нормализуется (`7` = `NT07`). `DELETE /{code}/check-in` отменяет отметку,
   `PATCH /{code}` меняет имя для табло.
4. `GET /participants` — список (доступен и судье); поле `category` видят только админ и суперпользователь.

Категория не попадает в журнал аудита: там только факт `category_set`.

## Жеребьёвка

Команда = m участников ОВЗ + m без ОВЗ; число команд всегда чётное, остальные идут в резерв.

1. `GET /api/v1/draw/options` — варианты m (команды и резерв), админ и суперпользователь.
2. `POST /api/v1/draw {"m": 2, "seed": 123}` — жеребьёвка; `seed` необязателен, результат
   детерминирован по `seed`. Протокол (seed, составы, резерв) хранится в таблице `draw`,
   читается через `GET /api/v1/draw`.
3. Повтор: только суперпользователь и только пока нет результатов секций, иначе `409`.
4. `GET /api/v1/teams` — команды, участники и дуэли с парами (доступно и судье, категории нет).

В журнал аудита попадают только `seed`, `m`, `team_count`.

## API станций и планшетов

Контракт — `shared/openapi.yaml`. Вызывающий — станция (заголовок `Authorization: Bearer <токен>`,
секция `bci`) или волонтёр (cookie, секция `physical`); остальные роли получают `403 forbidden`,
чужая дисциплина или секция — `403 wrong_discipline`.

- `GET /api/v1/me/config` — дисциплина, секция, время сессии.
- `GET /api/v1/participants/{code}/eligibility` — данные для окна «Это я» и список проблем.
- `POST /api/v1/sessions` — открыть сессию (только станция); повтор безопасен.
- `POST /api/v1/results` — результат сессии; идемпотентно по `session_id` (тот же хеш тела — `200`
  с тем же ответом, другое тело — `409 session_conflict`). Проблемы (`warnings`) не блокируют приём:
  результат из офлайн-буфера записывается всегда. Статус: станция — `entered`, волонтёр — `confirmed`.
- `POST /api/v1/stations/me/heartbeat` — состояние стенда; без heartbeat 30 с станция не блокирует
  участников (`busy_on_other_station`).
