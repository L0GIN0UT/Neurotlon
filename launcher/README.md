# Лаунчер стенда

Программа на ПК стенда: QR с вебки или ручной ввод ID, окно «Это я», запуск игры, отправка результата на сервер. Работает и без связи с сервером. Контракты: [`shared/openapi.yaml`](../shared/openapi.yaml), [`shared/game-launch.md`](../shared/game-launch.md), [`shared/participant-code.md`](../shared/participant-code.md).

Состоит из двух частей:

- **Окно** (`launcher/electron`, интерфейс `web/station.html`): Electron рисует экраны на HTML, снимает QR камерой, показывает результат.
- **Ядро** (этот пакет, Python): машина состояний, буфер результатов, клиент сервера, запуск игры. Окно запускает ядро само и общается с ним по локальному HTTP на `127.0.0.1`.

## Как стенд устроен для админа

1. В админке создать станцию нужной дисциплины и скопировать её токен.
2. Поставить на ПК стенда установщик «Нейротлон Стенд» (Windows, один для всех дисциплин). При первом запуске откроется экран «Настройка стенда»: адрес сервера, токен, камера для QR (список с превью), при самоподписанном сертификате — файл сертификата зала. Клавиатура нужна только на этом шаге.
3. «Проверить подключение» показывает, какая станция подключилась и сколько игроков нужно; «Сохранить и запустить» доступно только для проверенных значений.
   Игру выбирать не надо: все три входят в установщик, нужная берётся по дисциплине станции (файл можно указать и вручную).
4. Дальше стенд запускается сам и работает без админа: участник показывает бейдж, играет, видит результат (экран «Готово» 5 секунд), и стенд ждёт следующего.

Дисциплину в настройки не пишут: её сообщает сервер по токену, токен станции «Понг» сам включает двух игроков. Повторная настройка: Ctrl+Alt+S в окне. Токен при повторной настройке не показывается; пустое поле оставляет прежний. Упавшее ядро окно перезапускает через 2 с; после 5 падений за минуту окно закрывается с кодом ошибки. Выход: Ctrl+Q.

Игры подключаются файлом `.exe` (Unity) или любой командой, см. [`games/README.md`](../games/README.md). Лаунчер дописывает к команде `--launch <путь к launch.json>`.

## Установка и сборка

Нужны Python 3.12, `uv`, Node.js 24. Из корня репозитория:

```
uv sync
cd web && npm ci && npm run build          # интерфейс окна в web/dist
cd ../launcher/electron && npm ci          # один раз: Electron скачает свой движок
set NEUROTLON_LAUNCHER_CMD=uv run neurotlon-launcher
npx electron . --config путь\к\launcher.toml [--windowed] [--dev]
```

`--windowed` — обычное окно вместо киоска; `--dev` — инструменты разработчика и консоль страницы в stdout; `NEUROTLON_DEV_URL=http://127.0.0.1:5173/station.html` берёт страницу с `npm run dev`; без `--config` настройки лежат в `%APPDATA%\neurotlon-station-shell`.

Установщик Windows (NSIS, русский, с нашей иконкой и логотипом) собирает [`deploy/scripts/build-station-installer.ps1`](../deploy/scripts/build-station-installer.ps1): интерфейс, ядро лаунчера в `.exe` (PyInstaller) и сам установщик. Нужен интернет (движок Electron, NSIS); готовый установщик переносится на стенды без интернета.

## Файл настроек `launcher.toml`

Его пишет экран настройки; руками править не нужно. Поля:

- `server_url` — адрес ПК админа, только `https://` (токен идёт в каждом запросе); для разработки есть `allow_insecure_http = true`;
- `ca_file` — корневой сертификат зала; без него проверка идёт по системным сертификатам;
- `token_file` — файл токена (рядом, `station.token`; на Linux права 0600);
- `discipline` — необязательно, служит проверкой: если задана и не совпадает с сервером, стенд блокируется;
- `data_dir` — буфер результатов, кэш настроек, папки сессий, журнал `launcher.log`;
- `camera_name` — имя камеры для QR; нет — камера по умолчанию;
- `fallback_duration_s` — время игры, если настройки дисциплины ещё ни разу не получены (240 с);
- `[game]` — `command` (список: путь к игре и аргументы) и `workdir`;
- `[bridge]` — адрес BCI-моста, он передаётся игре.

Пример: [`launcher.example.toml`](launcher.example.toml).

## Что делает оператор и участник

1. Участник показывает QR бейджа камере или вводит номер на экранной цифровой клавиатуре (поле показывает префикс `NT`) либо с обычной (`NT07`, `nt07` или просто `7`); «Далее» или Enter. Esc стирает ввод.
2. Страница участника: имя или ID, команда с цветом. Если у него есть проблемы (нет отметки, уже проходил, играет на другом стенде, нет пары) или нет связи, показывается предупреждение; начать всё равно можно. «Играть» (Enter) или «Это не я» (Esc).
3. Понг: сначала левый игрок, затем правый; один и тот же участник дважды не принимается.
4. Идёт игра. По выходу игры результат ставится в буфер и уходит на сервер, показывается «Готово», затем снова ожидание.
5. Если игра упала, не уложилась в `duration_s + 420` с, не записала корректный `result.json` или сообщила `aborted`, появится «Техническая проблема»:
   - «Повторить» (Enter) — тот же `session_id` и те же участники, старый `result.json` стирается;
   - «Не пройдено» — каждому участнику уходит `not_completed` с причиной `equipment`. Только кнопкой, чтобы не нажать случайно.

## Без связи

- Нет связи при проверке ID: предупреждение «проверка не выполнена», игра начинается.
- Нет связи при старте сессии: игра идёт, занятость участника сервер не узнает.
- Настройки дисциплины (время игры) берутся из кэша `data_dir/config-cache.json`; если связи не было ни разу, берётся `fallback_duration_s` (240 с). Если стенд ещё ни разу не подключался и связи нет, ядро возвращает на экран настройки.
- Результат пишется в `data_dir/outbox.db` (SQLite, WAL) и пересылается по порядку с паузами 1, 2, 5, 10, 30 с. Повтор безопасен: сервер принимает результат идемпотентно по `session_id`. Буфер переживает перезапуск.
- Вверху справа «Связь есть» / «Нет связи» (по heartbeat), внизу «Ждут отправки: N». Если сервер окончательно не принял результат (409/422/403/404), он остаётся в буфере со статусом `rejected`, повторно сам не отправляется, внизу красная плашка. Список — нажатие на плашку или F2 (сессия, ID, ошибка); «Экспорт в файл» (кнопка или E) и каждое новое отклонение пишут `data_dir/rejected.json` для судьи.

## Разработка

```
uv run pytest launcher -q
uv run ruff check . && uv run ruff format --check . && uv run mypy
cd web && npm test
node --test launcher/electron/lib.test.cjs
```

Ядро не требует ни камеры, ни экрана. Окно для разработки без Electron: `uv run neurotlon-launcher --config … --ui-token <16+ символов> --ui-detached`, затем `npm run dev` в `web` и страница `/station.html?port=<порт>&token=<токен>`.

## Мост ядра и окна

`neurotlon-launcher --ui-token <16+ символов> [--ui-port N]` отдаёт состояние станции по локальному HTTP (`127.0.0.1`, каждый запрос с токеном запуска, чужой `Host` отклоняется) и печатает в stdout `{"ready": true, "port": N}`. Работает, пока родитель не закроет stdin. Если настроек нет, вместо станции работает экран настройки; после сохранения ядро выходит с кодом 75, и окно запускает его заново.

| Запрос | Что |
|---|---|
| `GET /api/state` | снимок: `discipline`, `players_needed`, `camera`, `status`, `state` (`kind`: idle, checking, confirm, starting, playing, done, problem, blocked, rejected, setup) |
| `GET /api/events?token=…` | поток Server-Sent Events: новый снимок при каждом изменении |
| `POST /api/command` | `{"action": "type_char", "value": "7"}`; допустимы только действия из белого списка |

Окно запускает ядро со случайным токеном запуска; страница получает адрес и токен только через preload и не может ходить никуда, кроме моста на `127.0.0.1` (политика CSP). Камера — единственное разрешение окна.

## Надёжность

- **Перезапуск посреди игры.** Перед запуском игры сессия записывается в `outbox.db`. После перезапуска ядро забирает готовый корректный `result.json` в буфер, а если его нет, показывает «Техническая проблема» для тех же участников.
- **Дерево процессов.** На Windows игра запускается в Job Object с `KILL_ON_JOB_CLOSE`: по таймауту или при закрытии лаунчера гибнет вся игра с дочерними процессами (запасной путь — `taskkill /T /F`). На Linux/macOS — отдельная группа процессов и `killpg`.
- **Проверка при старте.** Если в `launcher.toml` задана дисциплина, она сверяется с дисциплиной станции на сервере; при расхождении или неверном токене экран «Стенд остановлен».
- **Результат игры** проверяется теми же правилами, что на сервере (`wins` только в понге, при двух завершивших ровно одна победа); иначе — «Техническая проблема».
