# Лаунчер стенда

Программа на ПК стенда: вход по токену станции, QR с вебки или ручной ввод ID, окно «Это я», запуск игры, отправка результата на сервер. Работает и без связи с сервером. Контракты: [`shared/openapi.yaml`](../shared/openapi.yaml), [`shared/game-launch.md`](../shared/game-launch.md), [`shared/participant-code.md`](../shared/participant-code.md).

## Установка

Нужны Python 3.12 и `uv`. Из корня репозитория:

```
uv sync
```

1. **Токен станции.** В админке создайте станцию и скопируйте токен в файл, например `launcher/station.token` (одна строка). Файлы `*.token` и `launcher.toml` в `.gitignore`; сам токен в настройки не пишется.
2. **Настройки.** Скопируйте `launcher/launcher.example.toml` в `launcher/launcher.toml` и поправьте:
   - `server_url` — адрес ПК админа, только `https://` (токен станции идёт в каждом запросе); `http://` лаунчер не принимает, для разработки есть `allow_insecure_http = true` (в журнал пишется предупреждение);
   - `ca_file` — корневой сертификат зала, тот же, что ставится на планшеты; без него проверка идёт по системным сертификатам;
   - `token_file` — путь к файлу токена;
   - `discipline` — `darts`, `football` или `pong` (должна совпадать с дисциплиной станции на сервере);
   - `data_dir` — буфер результатов, кэш настроек, папки сессий, журнал `launcher.log`;
   - `camera_index` — номер вебки (0 — первая);
   - `fallback_duration_s` — время игры, если настройки дисциплины с сервера ещё ни разу не получены (по умолчанию 240 с);
   - `[bridge]` — адрес BCI-моста, он передаётся игре.
3. **Команда игры** — `[game] command`, лаунчер допишет `--launch <путь к launch.json>`:
   - pygame-ce: `command = ["python", "-m", "neurotlon_games.darts"]`;
   - Unity: `command = ["C:/neurotlon/games/Darts/Darts.exe"]`, при необходимости `workdir`;
   - без игры (разработка): `command = ["python", "-m", "neurotlon_games.stub", "--seconds", "5"]`. Флаги заглушки: `--abort` (игра прервана), `--crash` (падение), `--seed`.

Поведение игры — по [`shared/game-launch.md`](../shared/game-launch.md): читает `launch.json`, пишет `result.json` в `result_path` и выходит с кодом 0.

## Запуск

```
uv run neurotlon-launcher --config launcher/launcher.toml
```

Ключи: `--no-camera` — без вебки (только ввод ID), `--windowed` — окно вместо полного экрана. Выход: `Ctrl+Q`. BCI-мост (`neurotlon-bridge`) запускается отдельно до игры.

## Что делает оператор и участник

1. Участник показывает QR бейджа вебке или оператор вводит номер на экранной цифровой клавиатуре (стенд можно держать на сенсорном экране) либо с обычной (`NT07`, `nt07` или просто `7`), «Далее» или Enter. Esc стирает ввод.
2. Окно «Это я»: имя или ID, команда. Если у участника есть проблемы (нет отметки, уже проходил, играет на другом стенде, нет пары) или нет связи, окно жёлтое с пояснением; начать всё равно можно. «Это я — начать» (Enter) или «Это не я» (Esc). Цвет команды виден на круге с инициалом участника.
3. Понг: сначала левый игрок, затем правый; один и тот же участник дважды не принимается.
4. Идёт игра. По выходу игры результат ставится в буфер и уходит на сервер; экран «Готово» 5 секунд, затем снова ожидание QR.
5. Если игра упала, не уложилась в `duration_s + 120` с, не записала корректный `result.json` или сообщила `aborted`, появится «Техническая проблема»:
   - «Повторить» (Enter) — тот же `session_id` и те же участники, старый `result.json` стирается;
   - «Не пройдено» — каждому участнику уходит `not_completed` с причиной `equipment`. Только кнопкой, чтобы не нажать случайно.

## Без связи

- Нет связи при проверке ID: окно «Это я» жёлтое («проверка не выполнена»), игра начинается.
- Нет связи при старте сессии: игра идёт, занятость участника сервер не узнает.
- Настройки дисциплины (время игры) берутся из кэша `data_dir/config-cache.json`; если связи не было ни разу, берётся `fallback_duration_s` (240 с).
- Результат пишется в `data_dir/outbox.db` (SQLite, WAL) и пересылается по порядку с паузами 1, 2, 5, 10, 30 с. Повтор безопасен: сервер принимает результат идемпотентно по `session_id`. Буфер переживает перезапуск лаунчера.
- Вверху справа — «Связь есть» / «Нет связи» (по heartbeat), внизу — «Ждут отправки: N». Если сервер окончательно не принял результат (409/422), он остаётся в буфере со статусом `rejected`, повторно сам не отправляется, внизу красная плашка. Отклоняются также 403 и 404. Список — нажатие на плашку или F2 на экране ожидания (сессия, ID, ошибка); «Экспорт в файл» (кнопка или E) и каждое новое отклонение пишут `data_dir/rejected.json` для судьи.

## Разработка

```
uv run pytest launcher games -q
uv run ruff check . && uv run ruff format --check . && uv run mypy
```

Ядро (машина состояний, буфер, клиент, запуск игры) не требует камеры и экрана; `cv2` и `pygame` подключаются при запуске интерфейса и камеры.

## Надёжность

- **Перезапуск посреди игры.** Перед запуском игры сессия записывается в `outbox.db`. После перезапуска лаунчер забирает готовый корректный `result.json` в буфер, а если его нет, показывает «Техническая проблема» для тех же участников.
- **Дерево процессов.** На Windows игра запускается в Job Object с `KILL_ON_JOB_CLOSE`: по таймауту или при закрытии лаунчера гибнет вся игра с дочерними процессами (запасной путь — `taskkill /T /F`). На Linux/macOS — отдельная группа процессов и `killpg`.
- **Проверка при старте.** Дисциплина в `launcher.toml` сверяется с дисциплиной станции на сервере; при расхождении или неверном токене экран «Стенд остановлен».
- **Результат игры** проверяется теми же правилами, что на сервере (`wins` только в понге, при двух завершивших ровно одна победа); иначе — «Техническая проблема».
- Токен не должен читаться другими пользователями ПК (`chmod 600`); иначе в журнал попадёт предупреждение.

## Интерфейс на HTML в Electron

Основной вид стенда: окно Electron рисует экраны на HTML (страница `web/station.html`, исходники `web/src/station`), Python-лаунчер остаётся ядром (состояния, очередь, запуск игры). Pygame-интерфейс (`--ui pygame`, по умолчанию) — запасной.

Запуск на машине разработчика:

```
cd web && npm ci && npm run build          # собрать интерфейс в web/dist
cd ../launcher/electron && npm ci          # один раз: Electron скачает свой движок
set NEUROTLON_LAUNCHER_CMD=uv run neurotlon-launcher
npx electron . --config путь\к\launcher.toml [--windowed]
```

`--windowed` открывает обычное окно вместо киоска; `--dev` включает инструменты разработчика; `NEUROTLON_DEV_URL=http://127.0.0.1:5173/station.html` берёт страницу с `npm run dev` вместо собранной. Ctrl+Q закрывает окно и останавливает лаунчер. Камера для QR открывается в самой странице.

Окно запускает лаунчер как `--ui web` и передаёт ему случайный токен запуска; страница получает адрес и токен только через preload. Страница не может ходить никуда, кроме моста на `127.0.0.1` (политика CSP), камера — единственное разрешение.

### Первая настройка стенда

Админ настраивает стенд один раз, дальше лаунчер работает без него:

1. В админке создать станцию нужной дисциплины и скопировать её токен.
2. На ПК стенда запустить окно. Если настроек нет, откроется экран «Настройка стенда»: адрес сервера, токен, файл игры (`.exe`), при самоподписанном сертификате — файл сертификата зала. Клавиатура нужна только на этом шаге.
3. «Проверить подключение» показывает, какая станция подключилась и сколько игроков нужно. «Сохранить и запустить» доступно только для проверенных значений.
4. Настройки сохраняются в `launcher.toml` и `station.token` (папка `%APPDATA%
eurotlon-station-shell`, либо путь из `--config`); окно перезапускает лаунчер в рабочем режиме.

Дисциплину в файл не пишут: её сообщает сервер по токену, токен станции «Понг» сам включает двух игроков. Поле `discipline` в `launcher.toml` остаётся необязательным и работает как проверка (несовпадение блокирует стенд). Если связи нет и стенд ещё ни разу не подключался, лаунчер возвращает на экран настройки.

Повторная настройка: Ctrl+Alt+S в окне (или `--setup`). Токен при повторной настройке не показывается; пустое поле оставляет прежний. Лаунчер, упавший сам, перезапускается через 2 с; после 5 падений за минуту окно закрывается с кодом ошибки.

### Мост лаунчера

`neurotlon-launcher --ui web --ui-token <16+ символов> [--ui-port N]` не открывает окно сам: он отдаёт состояние станции по локальному HTTP (`127.0.0.1`, каждый запрос с токеном запуска) и печатает в stdout `{"ready": true, "port": N}`. Работает, пока родитель не закроет stdin. Окно с интерфейсом открывает Electron (`launcher/electron`).

| Запрос | Что |
|---|---|
| `GET /api/state` | снимок: `discipline`, `players_needed`, `status`, `state` (`kind`: idle, checking, confirm, starting, playing, done, problem, blocked, rejected) |
| `GET /api/events?token=…` | поток Server-Sent Events: новый снимок при каждом изменении |
| `POST /api/command` | `{"action": "type_char", "value": "7"}`; допустимы только действия машины из белого списка |

Pygame-интерфейс (`--ui pygame`, по умолчанию) остаётся запасным.
