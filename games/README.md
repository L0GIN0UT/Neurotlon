# Игры

Дартс, футбол и понг. Механика игр ещё не придумана, поэтому здесь лежит всё, кроме геймплея: запуск, датчики, таймер и отправка результата уже сделаны (калибровку датчиков проводит лаунчер, игра её только проверяет). Игру можно писать на pygame-ce (Python) или на Unity, одной командой проверяется, что она встанет на стенд.

## Как подключить игру

### Контракт простыми словами

Игра — любой исполняемый файл. Лаунчер запускает его как `<команда> --launch <путь к launch.json>` и ждёт `result.json`. Полное описание: [`shared/game-launch.md`](../shared/game-launch.md), схемы лежат рядом.

1. **Читает `launch.json`**: `session_id`, `discipline`, `duration_s`, участники (в понге у каждого `side`: `left` или `right`), адрес моста, `result_path`; необязательное `max_points` — лимит очков за секцию (дартс, футбол): `ResultWriter` не запишет `points` больше, у понга поля нет. `points` — целое число (решение 28): `completed()` и `ResultWriter` отклоняют дробное, проверка даёт FAIL.
2. **Подключается к BCI-мосту** ([`shared/bridge-protocol.md`](../shared/bridge-protocol.md)) и берёт значения сигналов 0…1. Значение может быть недействительным (артефакт, нет контакта): тогда очков не давать.
3. **Калибрует датчики**: если мост объявил `emg_cycle` в `hello.features`, ЭМГ идёт одним шагом `cycle` (20 с: напрячь и расслабить мышцу с датчиком по 5 с, дважды; фазу и обратный отсчёт присылает мост), иначе старыми `rest` 5 с и `contract` 12 с (3 раза по 3 с с паузой 1 с); ЭЭГ `baseline` 12 с с открытыми глазами, взгляд на точку по центру экрана. Показывает игроку инструкцию. Сбой шага: причина на экране и один повтор, потом `aborted`.
   Дартс и футбол запускают бросок и удар по событию `burst` (резкое сокращение, мост объявляет `burst` в `features`); `neurotlon-game-check` требует хотя бы одну реакцию на `burst` (игра набирает очки), для понга не требуется.
4. **Играет `duration_s` секунд** и по истечении завершается с текущими очками.
5. **Пишет `result.json`** во временный файл и переименовывает его: `finished` с записью на каждого участника или `aborted` с причиной. В понге ровно один победитель (`wins`: 1 и 0).
6. **Выходит с кодом 0.**

Также: Esc — прервать с подтверждением; датчик пропал — пауза, через 30 с `aborted`; в игре нет ФИО и других данных, кроме `code` и `display_name`.

### Путь Python (pygame-ce)

Пакет `neurotlon_games.sdk` берёт на себя пункты 1–6 и всё из «также». Игровой код — три метода:

```python
from collections.abc import Sequence

import pygame
from neurotlon_games.sdk import GameApp, LaunchInfo, ResultEntry, Signals, completed, run_game


class MyDarts(GameApp):
    def update(self, dt: float, signals: Signals) -> None:
        force = signals.value("emg")  # float 0..1 или None, если сигнала сейчас нет
        relax = signals.value("eeg")
        # здесь механика

    def draw(self, surface: pygame.Surface) -> None:
        # картинка; таймер и подсказки рисует GameApp
        surface.fill((0, 0, 0))

    def result(self) -> Sequence[ResultEntry]:
        return [completed(self.launch.participants[0].code, points)]


if __name__ == "__main__":
    raise SystemExit(run_game(MyDarts))
```

Начните с готового шаблона [`neurotlon_games/template.py`](src/neurotlon_games/template.py): шкала сигнала, очки копятся при значении выше 0,6; работает для дартса, футбола и понга. Скопируйте его, замените `update`, `draw` и `result`.

- Запуск без лаунчера: `uv run python -m neurotlon_games.template --launch путь\к\launch.json --windowed`.
- Понг: сторона игрока — `participant.side`, его сигнал — `launch.signal_of(participant)` (`emg_left` / `emg_right`).
- Очки — число от 0 до 1000. `wins` только в понге.
- Юнит-тесты игры без моста: `neurotlon_games.sdk.testing` (`FakeBridge`, `make_launch`, `make_signals`).

### Путь Unity

Папка [`unity/NeurotlonKit/`](unity/NeurotlonKit/README.md): локальный UPM-пакет без внешних зависимостей. Пошаговая инструкция (пакет, сцена, настройки сборки Windows, запуск с эмулятором) — в [README кита](unity/NeurotlonKit/README.md). Компонент `NeurotlonGame` делает то же, что `GameApp`, геймплей переопределяется в трёх методах.

Готовая игра: [`unity/Pong/`](unity/Pong/) — понг. Сила ЭМГ каждого игрока задаёт положение ракетки поперёк стола; счёт до 11, по времени побеждает ведущий, при равном счёте играется золотой мяч. Экран игроков делится пополам: у каждого вид от первого лица из-за своего края стола (слева красный, справа синий; там же инструкции и счёт). Для зрителей отдельный вид с табло на стене. Два экрана (монитор и телевизор): игроки на основном (1), зрители на втором (2), номер зрительского экрана — `--audience-display 1|2`. Один экран: `--view players|audience|all` (все три вида в одном окне), в игре F2 листает виды, F3 включает «все сразу». Для демонстраций: `--record <папка> [--record-seconds N]` сохраняет кадры экрана игры (потом собираются в видео ffmpeg). Правила и физика — `Assets/Scripts/Pong/PongRules.cs`, тесты — `Assets/Tests/EditMode`. Откуда взяты модели и звуки и как их пересобрать — `unity/Pong/ArtSource/README.md`.

Готовая игра: [`unity/Darts/`](unity/Darts/) — дартс (решение 30). Сосредоточение (`eeg`) задаёт светлый круг-«прожектор» вокруг центра мишени: чем оно выше, тем круг меньше; прицел гуляет внутри него. Бросок запускается резким сокращением мышцы (событие `burst` сигнала `emg`, сила на полёт не влияет; у старого моста без `burst` — сжатие руки, `emg` выше 0,6), дротик летит в точку прицела; пять бросков, за бросок 2 очка (центр), 1 очко или 0, максимум 10. Границы зон показаны кольцами на мишени, легенда слева. Правила и модель прицела — `Assets/Scripts/Darts/DartsRules.cs` (числа в `DartsTuning`), тесты — `Assets/Tests/EditMode`. Сцену собирает пункт меню `Neurotlon → Build Darts Scene` (`Assets/Editor/DartsSceneBuilder.cs`), её можно пересобрать после правки. Для демонстраций: `--record <папка> [--record-seconds N] [--record-all]`. Откуда взяты модели, дерево и звуки — `unity/Darts/ArtSource/README.md`.

Готовая игра: [`unity/Football/`](unity/Football/) — футбол (решение 31): полоса из четырёх элементов на поле стадиона. Змейка между конусами (положение мяча задаёт сила ЭМГ; три способа ведения, по умолчанию «газ и тормоз»; `--dribble level|throttle|rhythm`, клавиши F1–F3, окончательный выбор открыт), передача в ворота с чехлом и удар в круглую мишень (по три попытки: сосредоточение `eeg` сужает зону разброса, сжатие ноги `emg` бьёт в точку прицела), остановка мяча в зоне (нога тормозит). Очки за элемент 0–2, плюс до 2 за точность, максимум 10. Конусы, мячи, чехол и сетки двигаются по физике. Правила и числа — `Assets/Scripts/Football/FootballRules.cs` и `FootballTuning.cs`, тесты — `Assets/Tests/EditMode`, сцену собирает пункт меню `Neurotlon → Build Football Scene`. Для проверки без датчиков: `--demo right` (автоигрок делает всё правильно) и `--demo wrong` (всё неправильно); `--record <папка> --record-all` пишет кадры и журнал звуков для видео. Удар запускается резким сокращением мышцы (`burst`); сила сокращения удар не меняет, торможение и ведение идут по уровню `emg`. Происхождение графики и звуков с лицензиями — `unity/Football/ArtSource/README.md`.

### Порядок в Unity-играх

Все три игры идут одинаково: подключение и проверка готовности калибровки, обучение, отсчёт, зачётная часть. Сами датчики калибрует лаунчер до запуска игры (на каждого игрока в понге), игра калибровку не запускает: мост объявляет откалиброванные сигналы в `hello.calibrated`, а игра без калибровки на реальных датчиках сразу пишет `aborted` («датчики не откалиброваны: пройдите калибровку в лаунчере»). На эмуляторе (`state: emulated`) и у старого моста без `calibration_state` игра идёт без проверки. Если мост перезапустился и потерял калибровку (`not_calibrated` в сигнале дольше 2 с), игра пишет `aborted` («калибровка датчиков сброшена»); обрыв связи и устаревшие данные по-прежнему пауза и 30 с. Время зачётной части берётся из `duration_s` в `launch.json`; в дартсе и футболе таймер виден в верхней плашке, по истечении игра останавливается сразу и записывает набранные очки как `completed` (несделанное считается нулём). Понг идёт по правилам матча (до 11, золотой мяч), время из `launch.json` служит только предохранителем.

Обучение: игрок по очереди пробует каждую механику, перед ней своя короткая подсказка (3 с крупно, потом панель сбоку без затемнения). Шаг засчитан, когда механика сработала; не получилось за 20 с, шаг заново; после двух неудач «Позовите волонтёра». Enter у волонтёра пропускает шаг, шаги-проверки пропустить нельзя (волонтёр может только завершить игру: Esc, Enter, `aborted`, «демо-проверка не пройдена»). Очки обучения в результат не идут.
- **Дартс:** сосредоточение (круг сужается), бросок (напрячь мышцу выше линии), проверка: два попадания в зелёное или оранжевое кольцо из пяти бросков (квадратики бросков и «Попаданий: n из 2», заголовок «ПРОВЕРКА»).
- **Футбол:** два конуса (газ и тормоз), сосредоточение у мишени, удар, проверка: два попадания в мишень из пяти ударов, ворота, торможение, остановка строго внутри жёлтого квадрата.
- **Понг:** ракетка, удар, счёт (шаг засчитан, когда справились оба игрока); потом парная проверка (напрячь и расслабить мышцу, держать каждое положение около 0,3 с), отсчёт и карточка начала матча (3 с: «МАТЧ», до скольки, кто с кем, кто подаёт). Шкалы напряжения стоят в верхних углах на уровне имён на всех этапах.

В дартсе и футболе остались шкалы, нужные механике; длинные подсказки во время игры убраны. В футболе клавиши F1–F3 переключают способ ведения (для проверки владельцем), на экране они не показаны. Во всех играх тексты для игрока говорят «мышца с датчиком» (общие фразы в `NeurotlonTexts`). `--debug-score` (дартс и футбол: `0,9,10,25,100`, число меняется раз в 3 с; понг: `Л:П`) подставляет счёт только в подпись на экране, для проверки раскладки. На щитках арены и поля логотип проекта (`web/src/station/assets/logo.png`, копия в Assets каждой игры).

Как проверить руками: `uv run neurotlon-bridge --emulate --auto` (датчики сами, профиль `darts` или `pong`), `launch.json` из `shared/game-launch.md` (поставьте `duration_s` поменьше, например 60), запуск игры с `--launch launch.json`; параметр `--tutorial-min 10` замедляет обучение для показа. Автоматически: `uv run neurotlon-game-check --discipline darts|football|pong --duration-s 20 -- <путь к exe>`.

### Запуск с эмулятором

Датчики для разработки не нужны. Мост с эмулятором открывает окно, значения задаются клавишами (подсказки в окне):

```
uv run neurotlon-bridge --emulate --profile darts     # дартс и футбол: eeg + emg
uv run neurotlon-bridge --emulate --profile pong      # понг: emg_left + emg_right
```

Затем игра с `launch.json` (пример — в `shared/game-launch.md`; порт моста по умолчанию 8765).

### Проверка: `neurotlon-game-check`

Одна команда говорит, годится ли игра для стенда. Она поднимает эмулированный мост, сама двигает сигналы, запускает игру тем же кодом, что лаунчер (тот же таймаут `duration_s + 420 с` и завершение всего дерева процессов), и проверяет результат теми же правилами, что лаунчер и сервер:

```
uv run neurotlon-game-check --discipline pong -- python -m neurotlon_games.template
uv run neurotlon-game-check --discipline darts -- games\darts\Darts.exe
```

Команда игры идёт после `--`; `--launch <путь>` добавит проверка. Вывод: строка на проверку и итог.

| Проверка | Что значит |
|---|---|
| запуск | процесс стартовал |
| мост | игра подключилась к мосту |
| калибровка | мост проверки калибрует сигналы сам, как лаунчер (`cycle` для ЭМГ, `baseline` для ЭЭГ), до запуска игры; WARN, если игра сама отправила `calibrate` (её проводит лаунчер) |
| без калибровки | (PASS ставится по подстроке «калибр» в причине `aborted`: если Unity-игра меняет текст причины, в нём должно остаться это слово) вторым запуском мост не калибрует сигналы (как на стенде, где калибровку пропустили): игра должна сразу выйти с `aborted` и понятной причиной; FAIL, если зависла или упала, WARN, если дошла до конца |
| выход | вышла с кодом 0 за `duration_s` + запас |
| result.json | файл есть и проходит схему |
| session_id | совпадает с `launch.json` |
| статус, записи | `finished`, участники те же, целые `points` и `wins` по правилам сервера |
| победитель | только понг: ровно один |
| burst | дартс и футбол: мост прислал события `burst`, а игра набрала очки (SKIP, если за время игры событий не было; для понга не проверяется) |

Код выхода 0 только если нет ни одного `FAIL`; `WARN` не мешает. При `duration_s` = 10 проверка идёт около 20 секунд.

Полезные флаги: `--duration-s N` (от 10), `--max-points N` (положить `max_points` в `launch.json`; очки выше N дадут FAIL в проверке «записи»), `--keep ПАПКА` (оставить `launch.json`, `result.json`, `game.log`), `--no-uncalibrated-test` (не запускать игру вторым разом без калибровки), `--uncalibrated-wait-s N` (сколько ждать выхода игры без калибровки, по умолчанию 40), `--abort-test` (оборвать мост и посмотреть, прервётся ли игра; необязательно, итог только `WARN` или `PASS`). Остальные: `neurotlon-game-check --help`. Для игр на `GameApp` флаг `--time-scale 5` ускоряет таймеры (переменная `NEUROTLON_TIME_SCALE`, только для проверок).

### Подключение к стенду

В `launcher.toml` на стенде (см. [`launcher/README.md`](../launcher/README.md)):

```toml
[game]
command = ["python", "-m", "neurotlon_games.darts"]   # pygame-ce
# command = ["games/darts/Darts.exe"]                  # Unity
# workdir = "games/darts"
```

Лаунчер допишет `--launch <путь>`. Мост на стенде запускается отдельно (`start-bridge.cmd`), игре нужен только его адрес из `launch.json`. Лаунчер калибрует датчики перед запуском игры (экран «Калибровка») и закрывает связь с мостом: мост пускает одного клиента. Игры нового образца (без своей калибровки) ставьте на стенд только вместе с лаунчером, у которого есть этот экран: старый лаунчер не калибрует, и игра запишет `aborted`.

### Чек-лист перед мероприятием

- [ ] `neurotlon-game-check` проходит без `FAIL` для каждой дисциплины на том ПК, где будет стенд.
- [ ] Нет `WARN` про калибровку: игра сама не калибрует, а без калибровки прерывается (`без калибровки`: `PASS`).
- [ ] Игра запущена с настоящими датчиками из лаунчера: калибровка пройдена на экране лаунчера, значения двигаются.
- [ ] Выдернуть датчик в игре: пауза, через 30 с `aborted`; вернуть датчик в течение 30 с: игра продолжается.
- [ ] Esc во время игры спрашивает подтверждение; после подтверждения лаунчер показывает «Техническая проблема».
- [ ] Полный круг со стендом: скан QR, игра, результат на табло.
- [ ] Очки считаются по утверждённой методике (до её появления в игре стоят настройки по умолчанию).
- [ ] Игра запускается без интернета и без установки чего-либо поверх (шрифты и ресурсы внутри сборки).
- [ ] `.exe` или команда прописаны в `launcher.toml`, рабочая папка верная.
- [ ] Для понга проверены оба игрока: левый и правый датчик не перепутаны.
