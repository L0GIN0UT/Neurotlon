# BCI-мост

Отдаёт играм сигналы датчиков по протоколу из `shared/bridge-protocol.md` (TCP `127.0.0.1:8765`, NDJSON).
Два источника: эмулятор (значения с клавиатуры) и настоящие датчики BrainBit (ЭЭГ) и Callibri (ЭМГ).
Для игры они неотличимы.

## Команды

```
uv run neurotlon-bridge --emulate --profile darts     # эмулятор, окно с клавишами
uv run neurotlon-bridge --scan                        # найти датчики и выйти
uv run neurotlon-bridge --discover                    # фоновый поиск для лаунчера (JSONL в stdin/stdout)
uv run neurotlon-bridge --discover --fake             # то же на устройствах-подделках, без железа
uv run neurotlon-bridge --profile darts               # настоящие датчики, окно с живыми столбцами
uv run neurotlon-bridge --profile pong --headless     # то же без окна
```

- `--profile darts|football|pong` — набор сигналов (по умолчанию `darts`);
- `--port 8765` — порт;
- `--config путь\bridge.toml` — файл настроек (по умолчанию `bridge.toml` в текущей папке, затем рядом с исполняемым файлом);
- `--state-dir путь` — каталог для `calibration.json` (по умолчанию рядом с `bridge.toml`);
- `--headless` — без окна.

Коды выхода: `0` — нормально, `2` — ошибка настроек (нет `bridge.toml`, не указан серийный номер),
`3` — датчики недоступны (не загрузился NeuroSDK или нет Bluetooth-адаптера); причина печатается по-русски.

## Настройка: bridge.toml

```
copy bci-bridge\bridge.example.toml bridge.toml
uv run neurotlon-bridge --scan
```

Обычно датчики назначает экран настройки стенда в лаунчере (он ведёт поиск через `--discover`,
протокол в `shared/sensor-discovery.md`) и сам пишет `[devices]`. Вручную: `--scan` ищет и печатает вид, имя,
серийный номер и адрес каждого датчика, их вписывают в `[devices]`: `eeg = "серийный номер"` (старый вид)
или таблица `[devices.emg_left]` с `address` (главный ключ) и `serial` (запасной, если адрес сменился).

| Профиль | Нужные ключи в `[devices]` |
|---|---|
| `darts`, `football` | `eeg` (BrainBit), `emg` (Callibri) |
| `pong` | `emg_left`, `emg_right` (два Callibri) |

Если в `--scan` серийный номер пуст («неизвестен до подключения», так у Callibri), назначайте датчик по адресу: с серийным номером мост найдёт его только перебором при старте, это дольше. Поиск при старте заканчивается, как только нужный датчик нашёлся.
Разделы `[emg]`, `[eeg]` и `[alpha]` с параметрами обработки можно не трогать: значения проверены на железе в проекте neuro-biathlon,
комментарии в `bridge.example.toml`. Настоящий `bridge.toml` в git не попадает.

## Как работает

- На каждый датчик свой поток, свой обработчик и своя калибровка. В понге два Callibri работают одновременно и состояние не делят.
- ЭМГ: полоса 20–450 Гц, режекция 50 Гц, RMS за 100 мс каждые 20 мс. Калибровка: `rest` (медиана RMS за 5 с), затем `contract`
  (3 сокращения по 3 с с паузой 1 с, максимум — медиана пиков). Уровень `(rms - покой) / (максимум - покой)`, обрезан до 0…1.
  Первые 5 с после подключения сигнал оседает и не учитывается. Шаг `cycle` (рекомендуемый): напряжение, расслабление,
  ещё раз напряжение и расслабление по 5 с (или ритм `segments` из запроса игры); первые 1,5 с каждого сегмента не идут в
  расчёт, покой — медиана по расслаблениям, максимум — медиана пиков по напряжениям. `rest` и `contract` остались для
  выпущенных сборок игр.
- Резкое сокращение: по уровню 0…1 каждые 20 мс (`processing/burst.py`) мост шлёт играм событие `burst`. Нужно спокойное
  состояние перед фронтом, прирост не меньше `min_rise` за 150 мс и уровень не ниже `fire_level` три шага подряд; силу событие
  не несёт. Пороги в `[burst]` файла `bridge.toml` подбираются на стенде. Подробнее в `shared/bridge-protocol.md`.
- Калибровка датчиков живёт в процессе моста и сохраняется в `calibration.json` после каждого успешного шага; после перезапуска моста
  она восстанавливается, если файл не старше `ttl_h` часов (`[calibration]`, по умолчанию 4) и совпадает метод ЭЭГ; `reset`, неудачный шаг
  и новый шаг стирают её. Метод `emotions` не восстанавливается (параметры библиотеки не выгрузить). Мост сообщает готовые сигналы в `hello.calibrated`.
- ЭЭГ: метод выбирается аргументом `--eeg-method` (в обычной работе его передаёт лаунчер из настроек стенда, в `bridge.toml` метода нет).
  `alpha` (по умолчанию): относительная альфа по O1 и O2, окно 2 с, шаг 0,2 с, фильтры 1–40 Гц и режекция 50 Гц; мощность 8–13 Гц
  делится на мощность 4–30 Гц, перцентили калибровки задаёт `[alpha]`. `emotions`: расслабление из библиотеки Emotions.
  Калибровка `baseline` с открытыми глазами, 12 с (или `duration_s` из `calibrate`; у `alpha` первые 2 с уходят на набор окна, разумно не меньше 8 с), новый объект на каждую калибровку; в обоих методах сигнал `eeg` растёт с расслаблением.
  Артефакты дают `valid: false, reason: artifact`, обрыв данных (дольше 300 мс) в `alpha` — окно набирается заново, до этого `stale`.
- Потеря связи: датчик получает `disconnected`, при возврате фильтры сбрасываются, калибровка покоя и максимума сохраняется
  (идущая калибровка прерывается). Если связь есть, а данных нет 2 с, `StartSignal` отправляется повторно.
- Нет калибровки: `not_calibrated`; нет контакта электродов Callibri: `no_contact`; данные старше 500 мс: `stale`.

## Запуск на стенде

1. Включите датчики, вставьте Bluetooth-адаптер, закройте другие программы, работающие с BrainBit и Callibri.
2. `uv run neurotlon-bridge --profile <профиль>`: окно показывает по строке на сигнал: значение, столбец, состояние, заряд.
3. Откалибруйте датчики на экране «Калибровка» лаунчера и запустите игру: она подключается к мосту и проверяет, что калибровка готова (`hello.calibrated`). Игра калибровку сама не запускает. Без лаунчера калибровку можно запустить командой `calibrate` (см. `shared/bridge-protocol.md`) или взять эмулятор (`--emulate`), которому она не нужна.

## Проверка на железе (для владельца)

Автотесты идут на подделках SDK. Что нужно увидеть на настоящих датчиках:

Профиль `darts` (BrainBit + Callibri):
- [ ] `--scan` показывает оба датчика с серийными номерами, номера вписаны в `bridge.toml`;
- [ ] через 5–15 с оба сигнала `на связи`, заряд виден;
- [ ] Callibri: до калибровки `нет калибровки`; после калибровки (`rest`, затем `contract`, см. клиент) сжатие руки поднимает столбец `emg` до ~1, расслабление возвращает к 0;
- [ ] BrainBit: калибровка `baseline` доходит до «готово» за ~8 с (плюс ~4 с на старт библиотеки); при гримасах или движении головы значение `артефакт`;
- [ ] выключите Callibri: `нет связи`, включите: возвращается сам, без перезапуска моста.

Профиль `pong` (два Callibri):
- [ ] оба серийных номера (`emg_left`, `emg_right`) вписаны, обе строки `на связи`;
- [ ] калибровка каждой руки отдельно; сжатие левой руки двигает только левый столбец, правой только правый;
- [ ] калибровка одной руки не влияет на состояние другой;
- [ ] оба Callibri подключаются вместе с одного адаптера и держат связь минимум 5 минут.

Если что-то не работает, пришлите вывод в консоли (лог на уровне INFO) и результат `--scan`.

## Эмулятор: клавиши

| Профиль | Клавиша | Действие |
|---|---|---|
| darts, football | `W` / `S` | ЭЭГ: расслабление больше / меньше (0,5 в секунду) |
| darts, football | `A` (держать) | артефакт ЭЭГ |
| darts, football | Пробел (держать) | ЭМГ: сокращение |
| pong | левый `Shift` или `Q` | левая ЭМГ |
| pong | правый `Shift` или `P` | правая ЭМГ |

## Для игр

Игры импортируют только `neurotlon_bridge.client.BridgeClient`: `latest(signal)`, `calibrate(signal, step)`, `reset()`, `close()`.
Данные старше 500 мс приходят как `valid=False, reason="stale"`.
